## 10. Материалы и решения для рабочего запуска

| Что нужно | Для чего |
|---|---|
| Доступ к выбранному проекту Tilda и активный подходящий тариф | собрать и проверить страницы в реальной конфигурации |
| Фактический домен / HTTPS / утверждённые URL | адреса, OG и canonical после выбора домена |
| Согласование статуса LegacyLab | оставить портфолио-демонстрацию либо заменить условную компанию реальными сведениями |
| Достоверное описание услуг и границ работ | уточнить, кто поставляет, проектирует, монтирует и сопровождает |
| Подтверждённые товары, паспорта и разрешённые изображения | заменить условные IP/частоты/комплектацию и визуализации, если сайт станет коммерческим |
| Реальный получатель заявок, ответственный за обработку | подключить форму и проверить фактическое поступление |
| Утверждённые контакты, оператор данных, реквизиты при необходимости | наполнить контакты, политику и обязательную информацию |
| Документы под фактическую обработку | цели, получатели, хранение, контакты для обращений, согласие при необходимости |
| Канал для файлов, если нужен | в текущем демо готовый список вставляется текстом; загрузки файлов нет |
| Утверждение финальных изображений и лицензий | AI-иллюстрации остаются концептуальными, не паспортными фото изделий |
| Отдельное согласование открытой публикации | убрать noindex только после согласования и приёмки |

Не нужны для демонстрации: CRM, складской учёт, регистрация, оплата, личный кабинет, фиктивные отзывы. Если функциональность запросят позднее, она оценивается и реализуется отдельно.

## 11. Финальная проверка

| Критерий | Фактический статус |
|---|---|
| Понятное предложение | hero прямо называет радиосвязь, видео и доступ; обозначена комплектация под объект |
| Единая система | общий CSS, шрифт, кнопки и шаблон карточки на всех страницах |
| Осмысленный каталог | 12 позиций в 5 категориях, отдельные назначения, параметры и комплекты |
| Согласованные характеристики | проверены все строки карточек против единого источника данных |
| Следующее действие | подбор, КП, вопрос или переход в каталог доступны без регистрации |
| Ссылки имеют назначение | автоматическая проверка всех внутренних файлов/якорей прошла |
| Формы | DOM- и браузерные проверки ошибок, email/телефона и контекста прошли; реальной передачи нет |
| Поиск/фильтры/сортировка | DOM- и браузерные проверки категории, параметров, сброса, пустого результата и сортировки прошли |
| Мобильная версия | три основные страницы на пяти ширинах проверены; горизонтального переполнения нет |
| Контраст | основные текстовые пары ≥4,5:1 по расчёту; ключевые экраны осмотрены в браузере |
| Доступность | семантика, подписи, ошибки, alt и reduced-motion реализованы; Tab/Shift+Tab, Escape и возврат фокуса формы проверены; скринридер не тестировался |
| Доказательства опыта | вымышленных клиентов/сертификатов/сроков/результатов нет; кейс и каталог маркированы |
| Поддержка на Tilda | 15 страниц опубликованы через T123; каталог, формы и адаптив проверены на реальном адресе; нативный адаптер реальной формы не подключался |
| Закрытие индексации | meta на страницах + robots.txt + X-Robots-Tag локального сервера; параметры Tilda требуется перенести вручную |
| Публикация / реальные заявки | публикация выполнена; заявки остаются демонстрационными |

Автоматические проверки — `05-validation.md`. Выполненная браузерная проверка, измерения и снимки — `07-browser-qa.md`. Комплект готов для сборки. Проверка опубликованного экземпляра выполнена и описана в `08-tilda-publication.md`. Реальный приём заявок требует отдельного подключения и проверки.

### Проверки при последующих изменениях и перед реальным приёмом заявок

1. Повторить проверку трёх основных страниц на 1440, 1024, 768, 390 и 360 px: переносы, галерея, таблица, якоря и отсутствие горизонтальной прокрутки.
2. Пройти навигацию и формы с клавиатуры; проверить 200% масштаб, уменьшение движения и скринридер в целевых браузерах. Локальная проверка не подтверждает поведение после изменения блоков в Tilda.
3. Проверить каталог на опубликованных данных: радиосвязь/IP67, переключение на видео, поиск, чипы, пустой результат, сброс и сортировка.
4. Проверить контекст товара и объекта, затем фактическое поступление заявки подключённому получателю и поведение при ошибке сервиса.
5. Сохранять режим демо и noindex до согласования публикации. Отключить тестовый адаптер только после подключения реального сервиса и утверждения документов.
