# LegacyLab. Проект и визуальная система

## 1. Краткая концепция

LegacyLab — условный поставщик радиосвязи и систем безопасности для предприятий Казахстана. Аудитория: закупки, технические руководители, инженеры, службы безопасности, интеграторы и собственники. Сайт помогает собрать исходные требования, проверить подходящую модель и запросить предложение на комплект.

Характер: инженерный порядок, ясная документация, спокойная компетентность. Визуальная идея — «от требований к системе»: нумерованные разделы, точная сетка, предметная фотография, читаемые параметры. Никаких счётчиков достижений, фиктивных клиентов, сертификатов или наличия.

Основная конверсия: запрос подбора или КП. Дополнительные: каталог, характеристики, готовая спецификация, вопрос инженеру. Покупка в один клик, корзина, оплата и регистрация не используются.

## 2. Карта страниц и переходов

```text
/ Главная
  ├─ Оборудование → /catalog/
  │   ├─ категория → /catalog/?category=radio|video|access|network|accessories
  │   ├─ поиск / технические фильтры → параметры URL
  │   └─ Подробнее → /equipment/{id}/
  │       ├─ R-450: описание / характеристики / комплект / аксессуары
  │       ├─ запрос КП → модальная форма с моделью
  │       ├─ вопрос инженеру → форма с моделью и целью
  │       └─ аксессуары / похожие модели → их карточки
  ├─ Решения → /#solutions → форма с типом объекта
  ├─ Как работаем → /#process
  ├─ О компании → /#about
  ├─ Контакты → /#contacts → форма
  └─ форма / подвал → /privacy/
```

Выполнены три основных типа страниц. Чтобы «Подробнее» не вело на чужой товар, дополнительно созданы карточки оставшихся 11 моделей на том же шаблоне. На внутренних страницах навигация ведёт на якоря главной. Самостоятельная страница `/privacy/` описывает фактическую локальную обработку в демоверсии. Есть 404 с выходом в каталог.

Для Tilda подготовлена плоская карта адресов: `/`, `/catalog`, `/r-450`, остальные модели по артикулу, `/privacy`. Файл `tilda/route-map.json` задаёт преобразование; `tilda/native-cta-links.json` содержит готовые ссылки с параметрами формы. Это не обещание автоматического создания страниц в Tilda.

## 4. Подробная структура трёх страниц

### Главная

1. **Первый экран.** 12-колоночная композиция: текст около 6 колонок, рация около 6. Надзаголовок, H1 из задания, описание, два действия, три аргумента. Изображение без фальшивых графиков. Внизу инженерная подпись и география. Шапка 84 px, sticky в потоке, смещение якорей 104 px.
2. **Направления.** Пять категорий с пояснениями и предметной иллюстрацией. Карточка целиком ведёт в выбранную категорию; все ссылки доступны без наведения.
3. **Задача объекта.** Четыре направления в сетке 2×2, номер, задача, группы оборудования и действие с контекстом. На телефоне одна колонка.
4. **Популярное.** R-450, C-420, A-210, N-810. Четыре разных направления, согласованные параметры, без цен, скидок и отметок наличия. Маркировка демолинейки.
5. **Порядок работы.** Четыре этапа с общей линией и номером. Ни один этап не обещает неутверждённый срок.
6. **Пример решения.** Тёмная секция, складской комплекс, постановка, ограничения, состав, принципиальная схема, ожидаемый эффект. Контроллер, замок и регистратор названы зависимостями системы, а не выданы за отсутствующие товары каталога. На схеме нет монтажных точек и обещаний точного покрытия.
7. **О компании.** Иллюстративная архитектура и последовательность «требования → состав → совместимость → предложение». Изображение не обозначено как собственный объект.
8. **FAQ.** Пять полных ответов по списку задания; самостоятельные раскрытия. Вопросы о покрытии и совместимости объясняют, какие исходные данные нужны.
9. **Запрос.** Текст-помощник слева и форма справа. Имя, необязательная компания, контакт, необязательное описание; на странице видна маркировка тестового режима. Готовый список вставляется в описание: отдельной неработающей загрузки нет.
10. **Контакты/подвал.** Логотип, описание, навигация, география, переход к форме и документу демоверсии. Нет выдуманных телефонов, адресов и реквизитов.

### Каталог

Хлебные крошки → H1 → деловое пояснение → подписанный поиск → маркировка демонстрации. Desktop: фильтры 236 px + сетка 3 карточки. В шапке выдачи фактическое число моделей и работающая сортировка. Чипы фильтров стоят перед выдачей. При пустой выдаче сетка скрыта, показан полезный текст и два действия. После каталога — переход с готовым списком.

Категории: все, радио, видео, доступ, сеть, аксессуары. Во «всех» нет свалки технических фильтров. Для выбранной категории параметры строятся из фактических данных моделей. Между группами действует AND, внутри группы — OR. Любой фильтр можно убрать отдельно, все фильтры — сбросить одним действием. В 768 px две карточки, на телефоне одна, фильтры раскрываются кнопкой в потоке.

### Карточка R-450

Хлебные крошки → предметная визуализация и две технические схемы → маркировка Demo → единый H1, включающий модель и назначение → описание → диапазон/мощность/защита → условие стоимости → запрос предложения и вопрос инженеру. Переключаемая галерея содержит действительно три файла: фото, габаритную схему, органы управления.

Далее: якорная навигация → назначение и три сценария → таблица 10 параметров → комплект из шести пунктов → M-45/CH-45 → помощь с подбором → две другие радиостанции. Зарядный стакан входит в базовую комплектацию; отдельная позиция обозначена как дополнительное рабочее место. Документация без файла не обещается: кнопки скачивания паспорта нет, демонстрационное руководство указано только как условный состав комплекта.

## 7. Формы, поиск и фильтры

Обязательны только имя и контакт. Имя после trim не может быть пустым. Email проверяется на одну @, домен и суффикс; телефон допускает +, пробелы, дефисы и скобки, 10–15 цифр. Это проверка синтаксиса, а не подтверждение владения контактом. Компания до 160, имя до 100, контакт до 160, описание до 4000 символов.

Перед проверкой формы добавляются `source_page`, `product`, `direction`, `intent`; комментарий остаётся отдельным полем. Контекст виден пользователю, не требует ручного повторения. При смене CTA контекст обновляется; ранее набранный комментарий сохраняется в открытой странице. Скрытые поля предназначены для контекста, не для секретов.

| Состояние | Видимая реакция |
|---|---|
| Начальное | пустые поля, постоянные подписи, заметка о тесте |
| Ввод | синий фокус, после исправления исчезает ошибка |
| Ошибка | красная граница, текст у поля, aria-invalid, фокус первого ошибочного поля |
| Проверка | блокировка повторного нажатия, «Проверяем тестовый запрос…», aria-busy |
| Валидное завершение демо | «Проверка завершена. Запрос не отправлен», пояснение, скачивание JSON по действию |
| Успешная реальная отправка | только после подключения сервиса Tilda и фактического ответа; сейчас не используется |

Поиск: по модели и названию, без учёта регистра/ё, с нормализацией длинного дефиса. Несколько слов должны присутствовать в записи. Число результатов обновляется через role=status. В URL записываются только поисковые параметры, без контактов. Сортировка по умолчанию сохраняет исходный порядок, А–Я/Я–А меняет DOM-порядок по названию с numeric-сравнением. Ошибка загрузки JSON не маскируется пустым результатом: остаётся полный статический каталог и объяснение.

## 8. Правила адаптации

| Ширина | Правило реализации |
|---|---|
| 1440 | полезный контент 1200; поля 24 внутри контейнера; H1 60; 5 категорий; 4 популярных; каталог 3 |
| 1024 | полезный контент 976; меню ещё полное, компактная типографика; каталог: sidebar 210 + gap 24 + 3 карточки |
| 768 | шапка 76 и мобильное меню; hero ещё 2 колонки; 3 категории + последняя на 2 колонки; популярные 2; каталог 2 + sidebar |
| 390 | поля 20; H1 38; hero 1 колонка; кнопки одна под другой; каталог 1; фильтры раскрываются в потоке |
| 360 | поля 16; H1 35; основные кнопки hero одна под другой; каталог 1; подвал 1 колонка |

На ширинах до 700 px назначение, параметры и CTA товара идут перед галереей. Таблица характеристик остаётся двухколоночной, допускает переносы внутри значений; горизонтального скролла таблицы нет. Высота не фиксируется для текстовых секций. Галерея и изображения object-fit: contain; архитектура object-fit: cover.

Большинство кнопок минимум 44–50 px. Карточка категории и товара имеет крупную кликабельную область; её нижняя ссылка не требует наведения. Мобильное меню закрывается после перехода и по Escape. Встроенный dialog дополнен циклическим переходом фокуса по Tab/Shift+Tab. В браузере подтверждены удержание фокуса, закрытие по Escape и возврат на исходную кнопку. Автовоспроизведения, параллакса и перехвата прокрутки нет. Переходы 180–200 мс; prefers-reduced-motion отключает анимацию и transitions. Контент не скрывается до срабатывания IntersectionObserver.

Правила реализованы в CSS. Три основные страницы проверены в браузере на всех пяти ширинах; горизонтального переполнения нет. Измерения, снимки и ограничения проверки — в `07-browser-qa.md`.
