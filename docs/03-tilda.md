# Сборка LegacyLab на Tilda

## Выбранная конфигурация и проверенные возможности

Базовая конфигурация — **Tilda Personal, один многостраничный сайт**. Business нужен, если потребуется экспорт сайта или больше одного сайта. Сайт является B2B-витриной; платёжные системы и корзина не включаются. Согласно [официальной странице тарифов](https://tilda.cc/pricing/), Personal даёт полный набор блоков и подходит для одного сайта с каталогом. Проверено 02.11.2026 по публичной документации; на момент подготовки комплекта доступность в аккаунте не проверялась; фактический статус после переноса указан выше.

Подтверждены публичной документацией:

| Возможность | Источник и применение |
|---|---|
| HTML/CSS/JS в T123 | [Вставка HTML](https://help.tilda.cc/html). Для независимого каталога и небольших расширений. Проверять на опубликованной тестовой странице; редактор не исполняет весь код |
| Поиск и фильтры товарного каталога | [Фильтры товаров](https://help-ru.tilda.cc/online-store/filters). Нативная альтернатива кастомному виджету, если точность его UX не требуется |
| Скрытые поля и переменные формы | [Настройки форм](https://help.tilda.cc/forms/settings). Для модели, направления, цели и источника |
| Предзаполнение через URL | Там же: `form-setter-ИмяПеременной=Значение`, действует на опубликованной странице |
| Auto Layout | [Auto Layout в Zero Block](https://help.tilda.cc/zero-auto-layout). Для уникального hero без ручного абсолютного размещения всех текстов |
| Адаптив Zero Block | [Responsive Design](https://help.tilda.cc/zero/advanced). Сверять базовые диапазоны и реальные промежуточные ширины |

Это описание исходной проверки возможностей платформы. Фактически выполненная сборка и её ограничения указаны выше. Не приобретать тариф и не подключать сервисы автоматически: для работы текущего офлайн-комплекта это не требуется.

## Рекомендуемый способ: редактируемый контент + отдельный интерактивный каталог

Главную собрать стандартными блоками, уникальный первый экран — Zero Block с Auto Layout. Каталог — один T123 с подготовленным кодом; данные редактируются в одном источнике. Карточка R-450 может быть собрана стандартными блоками или использована как готовая вставка T123. Общую шапку/подвал назначить через настройки сайта. Эту схему выбираем, чтобы тексты маркетинговых разделов оставались удобны для редактирования.

Номера стандартных блоков намеренно не фиксируются там, где подходит несколько вариантов библиотеки: назначение и настройки ниже однозначны, а состав библиотеки может отличаться. T123 указан точно, поскольку он проверен по документации. При выборе блока проверить наличие нужного числа колонок, постоянных подписей полей и поведения меню.

## Готовый дополнительный код

`tilda/sections/catalog.html` — законченный каталог с формой демоподбора. Содержит разметку карточек, встроенный JSON, стили и JS; работает без приватных API Tilda, не считывает её внутреннее хранилище. Технические фильтры строятся из записей выбранной категории. Для включения именно этого UX нативный ST-каталог на той же странице не нужен. Источник — `tools/build.py`, генерирующий `catalog.json` и HTML. Не обещается синхронизация с встроенным товарным каталогом, CRM или складом.

Если позже выбран **нативный каталог Tilda**, данные переносятся через интерфейс/импорт с проверкой актуального шаблона CSV Tilda, а кастомный виджет убирается. При этом повторно тестируются динамическая релевантность фильтров, внешний вид карточки и CTA без корзины. `catalog.csv` — универсальная таблица передачи данных, **не** обещанный импортный формат Tilda. Не загружать её вслепую как готовый файл Tilda.

`tilda/embeds/` содержит полные страницы с шапкой и подвалом. Это удобный способ согласовать точный макет, но не автоматическое превращение HTML в стандартные редактируемые блоки. На одну страницу вставлять **один** такой файл. Не ставить вместе `embeds/catalog.html` и `sections/catalog.html`: будут дубли ID, шапки и формы. На гибридной странице `sections/…` дополнить нативными шапкой и подвалом.

### Изображения и стили вставок

Без параметров экспорта скрипт создаёт самодостаточные вставки с изображениями и шрифтом в data URL. Для опубликованного экземпляра уже применены `--asset-map tilda/asset-map.json --native-font`: используются CDN Tilda и штатный Inter. При выборе другого HTTPS-хранилища можно пересобрать с его фактическим адресом:

```powershell
python tools/export.py --asset-base https://ваш-фактический-хост/legacylab/assets/
```

Аргумент — фактическая папка HTTPS, не произвольный домен из примера. Скрипт принимает и `--asset-map путь-к-json`: JSON-объект `имя-файла → настоящий HTTPS URL`. Для файлов с индивидуальными URL Tilda это предпочтительно. Все имена assets перечислены в `dist/assets/`. Если часть карты отсутствует, скрипт оставит для этих файлов data URL, поэтому потерянные картинки не появятся молча. Фактические изображения теперь размещены на CDN Tilda; готовая карта адресов приложена.

У стилей общий префикс `.ll-site`, чтобы не менять нативные блоки. Для реальной публикации лучше вынести общие CSS/JS и шрифт в общие файлы и кешировать. Сохранить офлайн-сборку отдельно. SVG можно загрузить в Tilda как изображения; если конкретный выбранный блок его не принимает, экспортировать утверждённую схему в PNG нужной плотности, сохраняя alt.

## Настройка реальной формы

Текущие HTML-формы намеренно **никогда не отправляют сеть**. Переключателя, который тайно начнёт передачу данных, в прототипе нет. Для рабочего сайта рекомендуем стандартную форму Tilda с согласованным получателем.

| Переменная | Поле | Обязательность |
|---|---|---|
| name | однострочное, «Имя» | да |
| company | однострочное, «Компания — необязательно» | нет |
| contact | обычное однострочное, «Телефон или email» | да; не выбирать только Email или Телефон |
| comment | многострочное, «Описание задачи — необязательно» | нет |
| source_page | скрытое | заполняется контекстом |
| product | скрытое | модель, если выбрана |
| direction | скрытое | объект, если выбран |
| intent | скрытое | цель обращения |
| ll_form_mode | скрытое, значение `demo` | управляет fail-closed тестовым режимом расширения |

1. Создать стандартный блок формы, указать имена переменных точно как в таблице. Подписи сохранять над полями. Добавить якорь `request` перед блоком. Перенести визуальные токены, не включать тяжёлые эффекты.
2. Добавить `tilda/native-form-enhancement.js` в T123 внутри `<script>…</script>` после блока формы. Код использует обычные элементы формы и переменные, не внутренние ID Tilda. Он проверяет объединённое контактное поле, показывает контекст и по умолчанию блокирует передачу. `demo` — безопасное значение для согласования макета.
3. Ссылки CTA взять из `native-cta-links.json`. Например, ссылка R-450 передаёт product, intent и source_page, затем ведёт к `#request`. На главной направление передаётся аналогично. Не подставлять контакт или комментарий в URL.
4. В настройках Tilda «Формы» подключить согласованный сервис, подтвердить его в аккаунте владельца, отметить его в конкретном блоке. Проверить, где хранится заявка и кто имеет доступ. Встроенные записи Tilda и внешний получатель — разные точки проверки.
5. Утвердить документы и заменить пояснение о локальном деморежиме текстом фактической обработки. Текст реального успеха: «Запрос принят. Свяжемся с вами по указанному контакту, чтобы уточнить задачу». Показывать его штатным механизмом только после ответа Tilda; JS-расширение не создаёт собственный ложный успех.
6. Только на рабочем экземпляре выставить `ll_form_mode=live`, опубликовать закрытую тестовую страницу и проверить email и телефон, ошибку, повторное нажатие, модель/направление/комментарий. Убедиться, что тест реально появился у выбранного получателя, а не только в интерфейсе сайта.

Расширение подготовлено, но не испытано на DOM конкретного блока Tilda. После выбора блока это обязательная интеграционная проверка, особенно для нативной валидации и событий отправки. Прототип и нативное расширение — два альтернативных обработчика: не подключать оба к одной форме.

## Настройки страницы и SEO

Title/description берутся из `02-copy-deck.md`, не дублируются между страницами. H1 один, главный заголовок; номера разделов не превращать в H2. Заголовки секций H2, товарные/отраслевые H3. Для каждого изображения переносить alt из HTML. Общий favicon — `favicon.svg`, превью ссылки — `og.jpg`, 1200×630. Перед публикацией Tilda загрузить их штатно и проверить превью. У standalone-демо og:image относительный, в рабочей версии задаётся полный фактический URL на вашем домене; выдуманного canonical сейчас нет.

До согласования оставить robots meta из `head-demo.html` на всех страницах и запрет индексации в настройках. Для приватной передачи использовать защиту доступа средствами выбранного хостинга/Tilda; noindex не является ограничением доступа. Не путать опубликованный закрытый тест с согласованным запуском рабочего сайта.
